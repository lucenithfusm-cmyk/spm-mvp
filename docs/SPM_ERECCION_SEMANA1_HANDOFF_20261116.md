## Instrucciones técnicas vinculantes
1. Los siete archivos de imagen vienen del ZIP **SPM_Ereccion_Firmeza_Semana1_7_Pantallas_Boceto.zip**, y las otras siete imágenes de la serie original también están conservadas. El ZIP no está publicado como assets porque esta etapa prepara la lógica y las voces.
2. Las imágenes deben ser **la interfaz visible**, no una tarjeta estática acompañada de un nuevo formulario largo. Superponer zonas táctiles accesibles sobre controles aprobados y, cuando se amplíe, usar subpantallas igualmente premium.
3. Un único acceso desde **Hoy**. Para el perfil `erection` y días 1–7, el punto de entrada debe abrir una pantalla del contrato, sin lanzar además el formulario heredado ni el modal secundario de DE para la misma actividad.
4. Mantener la fuente de verdad de progreso: `SPM_DAILY_PRACTICE.saveActivity('main', record, userId+':'+planId, day)`. Para los días 1–5 integrar/conservar los campos que valida `SPM_ERECTION_PRACTICE.valid`, o extender esa validación mediante una migración compatible. **No usar localStorage paralelo** para completar el día.
5. **Día 6:** usar solo `SPM_PELVIC_LAB.openScheduled` y elegibilidad clínica existente, no crear otro entrenador. Lab semanal 1 vez; contracción/fuerza máx. 2 veces/semana si corresponde. El audio introduce, no ordena hacer fuerza a todos.
6. **Día 7:** revisión breve y repetición de una herramienta ya practicada; guardar resultado como `main` y regresar a Hoy.
7. Si hay señal clínica `urgent`, mantener bloqueo de prácticas. Las revisiones educativas bajo `review` siguen las restricciones ya definidas en `daily-practice-v1.js`. Nunca borrar flags ni modificar evaluación.
8. El audio se invoca con `SPM_ERECTION_WEEK1_BLUEPRINT.play(day, 'intro'|'close'|0|1|2)`. `stop()` debe llamarse al navegar. Se incluye texto locutable completo y **síntesis de voz del navegador** como audio temporal funcional. No inventar MP3 final ni redirigir un enlace de voz de terceros como un archivo MP3. Sustituir por siete grabaciones premium sincronizadas cuando estén disponibles.
9. Mantener botones Anterior, Siguiente, bocina, selección táctil, Finalizar y Volver a Hoy; sin nuevos cuadros duplicados de texto.
10. Subir assets aprobados a `premium-v2/assets/erection-week1/`, incluir script en `premium-v2/live.html` **antes de** `erection-practice-v1.js`, crear el bridge de táctil. Ejecutar pruebas de escritorio/iOS, seguridad, persistencia, retorno y compatibilidad con los 28 días.
11. Esta rama conserva la pausa comercial y no altera el despliegue de producción hasta completar pruebas. 
12. No modificar otros dominios ni reescribir los 21 días restantes.
